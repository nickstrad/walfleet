# Chapter 8 — Knowledge check answers

1. **100-byte open and double page-1 read at the first statement.**
   - `openDatabase` (`src/main.c:3360-3716`) calls `sqlite3BtreeOpen` (`src/btree.c:2532-2825`), which opens only the `.db` file descriptor and calls `sqlite3PagerReadFileheader` to read the first `100` bytes at offset `0` (to learn page size and reserve bytes). It allocates an empty `Schema` struct and deliberately defers reading `sqlite_schema` until the first SQL statement calls `sqlite3ReadSchema` (`src/prepare.c:470-484` -> `sqlite3Init` -> `sqlite3InitOne`), so `SCHEMA_USED` stays `0` at open regardless of table count.
   - On the first statement against a WAL database, `btreeBeginTrans` (`src/btree.c:3598-3804`) calls `lockBtree` (`src/btree.c:3282-3459`) in a loop (line `3711`). The first `lockBtree` reads page 1, sees header byte `19` = `2` (WAL read version), opens `-wal` and `-shm` via `sqlite3PagerOpenWal`, and drops page 1 without keeping it (`src/btree.c:3333-3352`) because a newer version of page 1 might already be in the WAL. `btreeBeginTrans` then calls `lockBtree` a second time, reading page 1 again through the WAL-aware pager.

2. **`PRAGMA default_cache_size` and `VACUUM INTO`.**
   - The deprecated `PRAGMA default_cache_size` stores a 4-byte integer in database header bytes `48–51` (`BTREE_DEFAULT_CACHE_SIZE`). In `modernc.org/sqlite v1.60.1`, `SQLITE_OMIT_DEPRECATED` is not defined, so `sqlite3InitOne` (`src/prepare.c:323-333`) checks whether the connection's `cache_size` is still unset (`0`) and, if so, initializes it to `sqlite3AbsInt32(meta[BTREE_DEFAULT_CACHE_SIZE-1])` (falling back to `SQLITE_DEFAULT_CACHE_SIZE` = `-2000` only when bytes `48–51` are `0`). A platform must therefore set `PRAGMA cache_size` explicitly on every open.
   - `VACUUM INTO` preserves `page_size`, `auto_vacuum`, `encoding`, `user_version`, `application_id` (and `default_cache_size`, confirmed by `OPN-04c`), but writes a rollback-mode output file with header bytes `18–19` = `1` (`journal_mode = delete`). A platform that rebuilds a database through `VACUUM INTO` must switch the output back to `PRAGMA journal_mode=wal` before putting it back into service.

3. **Uncounted RSS, process-wide `PRAGMA shrink_memory`, and descriptor parking.**
   - **Uncounted RSS (about `31.7 MiB`, `162 KiB/connection` in one lab run of 8.2 B; RSS is run-dependent):** `CACHE_USED`, `SCHEMA_USED`, and `STMT_USED` omit the per-connection `48 KiB` lookaside buffer (`1200` × `40` at `src/global.c:218-224`; `LOOKASIDE_USED` counts slots, not bytes), `modernc.org/sqlite` and `modernc.org/libc` per-connection structures, and allocator size-class overhead (such as 4.3 KiB page allocations landing in 8 KiB slots). As adversarial test `IDL-03a` showed (`319–321 KiB/conn` with 1,000-table schemas), this uncounted part grows with schema size and must be measured for a platform's own schema.
   - **Process-wide `PRAGMA shrink_memory`:** `PRAGMA shrink_memory` (`src/pragma.c:2439-2442`) calls `sqlite3_db_release_memory` (`src/main.c:897-915`) -> `pcache1Shrink` (`src/pcache1.c:839-851`), which sets the `pcache1` **group's** `nMaxPage` to `0` and runs `pcache1EnforceMaxPage` (`src/pcache1.c:621-637`). Because `modernc.org/sqlite` is built with `SQLITE_ENABLE_MEMORY_MANAGEMENT`, all connections share one group, so shrinking connection 0 evicts unpinned pages from all `200` connections (`52,961` -> `5,089` bytes each) while leaving `SCHEMA_USED` and `STMT_USED` unchanged.
   - **Descriptor parking (`5 -> 4 -> 0` in 8.2 D):** Two WAL connections to the same file in one process share one `-shm` descriptor (`unixShmNode`), using `5` descriptors (`2× .db`, `2× -wal`, `1× -shm`). When connection 2 closes while connection 1 still holds its WAL `SHARED` lock on `t.db` (`pInode->nLock > 0`), `unixClose` (`src/os_unix.c:2341-2371`) cannot call `close()` on connection 2's `.db` descriptor because closing any descriptor to an inode drops all of the process's POSIX locks on that inode. Instead it parks the descriptor via `setPendingFd` (`src/os_unix.c:2101-2109`, leaving `4` open descriptors) until connection 1 closes and `closePendingFds` (`src/os_unix.c:1471-1482`) releases all parked descriptors (`0`).

4. **Experiment 8.3 Part B: B2 vs B3 vs B5.**
   - **B2 (unclosed `*sql.Rows`):** Committed step 1 stays in `-wal` because `(*sql.DB).Close()` closes only idle connections in Go's pool and returns `nil` without calling the driver's `Close` while `rows` holds the connection checked out. `connmgr` sees `e.db.Stats().OpenConnections == 1` and **skips `CheckAtRest`** because `CheckAtRest` opens and closes the `.db` file, which on Unix would strip the still-open connection's POSIX locks (demonstrated in rollback mode by `ATR-02`). Once `rows.Close()` runs, the connection closes cleanly and checkpoints step 1 into `.db`.
   - **B3 (killed writer):** Committed step 1 stays in the `90,672`-byte `-wal` (with `-shm` present). Copying `db-0002.db` alone (`naive-copy.db`) produces a valid SQLite file holding **step 0 (exact bytes)**, silently losing step 1. One clean open and close recovers `-wal`, checkpoints step 1 into `.db`, and unlinks both side files.
   - **B5 (file renamed while open):** `sqlite3PagerClose` (`src/pager.c:4222-4279`) checks `databaseIsUnmoved` (`src/pager.c:4188-4205` -> `fileHasMoved`, `src/os_unix.c:1623-1632`), sees that the path's inode no longer matches the open descriptor, and omits the checkpoint buffer passed to `sqlite3WalClose`. Step 1 remains in the `90,672`-byte `-wal` under the **old** filename, while `moved.db` has no side files and no locks—so `moved.db` **passes every at-rest check yet silently holds step 0**.

5. **Side-file checks, the `fcntl(F_GETLK)` lock probe, and remaining blind spots in `CheckAtRest`.**
   - Side-file checks (`-wal`, `-shm`, hot `-journal`) miss two active cross-process readers: a WAL connection with `PRAGMA locking_mode=EXCLUSIVE` keeps its wal-index in heap memory and creates **no `-shm` file** (`ATR-01b`), and an active rollback-mode reader creates no sidecar file at all.
   - Probing SQLite's POSIX lock range (`0x40000000`, length `512` bytes: `PENDING`, `RESERVED`, and `SHARED`) with `fcntl(F_GETLK)` (`lockedByAnotherProcess`) catches both because both hold POSIX locks on the `.db` file.
   - Two cases remain invisible to `CheckAtRest`: (a) a connection in another process that currently holds **no lock**—an idle rollback-mode connection, or a connection that opened the file without yet running a statement (`ATR-01a` case 3); and (b) another open `*sql.DB` to the same file inside the **same** process (`F_GETLK` never reports the calling process's own locks, and running `CheckAtRest` while the process holds another connection would drop that connection's locks). Ensuring no outside opener exists is therefore a platform ownership rule, not something `CheckAtRest` can guarantee alone.
